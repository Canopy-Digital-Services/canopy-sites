# The tool layer and site editing

Code paths are relative to `apps/portal/`.

`src/lib/site-tools/` is the only path for edits to a site's content (PRD D8, D9): ownership, the lane (the contract's `laneViolations`: Canopy's fields, the site's locks and fixed lists as address patterns, PRD D50), the contract with the site guide's limits, counts, and refused phrases, and rate limits are enforced here for every source (Editor, quick edit, later MCP). One person edits a site at a time (PRD D64): every write first takes or keeps the site's hold for its caller (`requireHold`, over `hold.ts`, the only code that touches `site_holds`), ahead of its rate limit, and is refused with a `ToolError` carrying `heldBy` while someone else's hold is live. A hold starts with an edit and never with a page: a person's own, not a browser's, it is given up by a publish or a discard that leaves no draft (`doneEditing`) and at sign-out, and otherwise runs out (`HOLD_TTL_MS`). The draft is its author's (`ChangeSet.updatedByUserId`): a write that adds to it (`saveDraft`, `proposeChange`, Quick Edit's `holdSite`) calls `requireEdit`, which refuses anyone else with a `ToolError` carrying `draftBy`, before taking any hold, while publish and discard stay open to everyone on the account under `requireHold`. A draft with no author recorded (they were taken off the account) is anyone's to carry on. Reads stay open to everyone on the account. A new write to a site's content starts with the same call. Between writes the editing pages follow the hold through `SiteHoldProvider` (`src/components/sites/site-hold.tsx`): it asks the `keepHold` action about every 25 seconds while its person is active and stops after ten quiet minutes (`src/lib/site-hold-policy.ts`), which keeps a hold its person has and takes none. Only `begin()`, which the Editor calls when a field is opened, asks to take it before a write. While someone else has the site, Quick Edit shows `SiteNotice` in place of the chat, the Editor puts its canvas behind `BehindGlass`, the preview bar says who where Publish would be, and the Sites chrome's `DraftStatus` leaves out Discard (from `getDraftState`'s `heldBy`, looked up again on the provider's `HOLD_CHANGED`), all worded by `editingNotice`. While the draft is someone else's and they have stopped, the same two places say so (`draftNotice`, with what it changes), Publish and Discard are offered, and discarding asks first and names its author. The preview page passes `reload={false}`: it follows the draft itself, and a refresh from the provider would remount it. Every answer carries a marker of where the draft and the published list stand. When it moves without the page's own doing, the provider fires `SITE_MOVED` and the editing surface mounts again, so nothing edits on top of content it never saw; a page's own write adopts its marker (`wrote`, or the `DRAFT_CHANGED` event). The Editor's unsent edits (`src/lib/unsaved-edits.ts`) are kept with the marker they were typed at and dropped, with a message, once it has moved. A draft is named to anyone but its last editor (`theirChanges`, from `getEditorChanges`' `by`). A page renders from `getSiteEditing`, which takes nothing; a new page that edits a site's content follows the hold the same way, and never takes it for being open. A lock or fixed list that isn't an address refuses every edit rather than letting one through. The contract runs over the whole draft, but the guide's limits, counts, and refused phrases apply only to what the edit changed (a field whose value it changed or added, a list it lengthened, compared by address, `guideIssues`), so copy the published site already has past a rule never refuses an edit elsewhere; the operator's site page lists that copy (`publishedGuideIssues`). Publish runs `check` again on the draft's base commit, so a lock, fixed list, or guide rule added since the draft was saved applies to it, and a draft that fails is marked `FAILED`. The builder keeps its builds in memory and answers 404 for one it lost in a restart: `refreshChange` starts it again, once per draft version (`rebuildLost`), and treats any other builder failure as no news. Every write returns what it changed, field by field (`changes.ts`), and what the guide's `avoid` flags in text it changed; quick edit's tool result carries both to the model. A refusal that is Canopy's call (the lane, a refused phrase) is a `ToolError` with `outOfLane`, on which quick edit tells the model to draft a request instead of trying another way. Help requests (`help-requests.ts`, PRD D34): quick edit's `request_help` drafts one, the owner sends or dismisses it from a card (`HelpRequestCard`), a sent one emails every Global Admin from the Sites sender with the owner as Reply-To, and the operator closes it with an optional note emailed back; one sent while acting emails nobody. Text quick edit won't put on the site is drafted with `refused` set, and reaches Canopy, marked Refused, only if the owner sends it. Quick edit's prompt is `BASE_RUNBOOK` (`src/lib/quick-edit/runbook.ts`) plus the prose of the site's `SITE_GUIDE.md`, from the draft view. A failed builder call reaches the owner, and quick edit's model, only as a plain sentence from `builder-failure.ts`, which logs the builder's message with the site's slug; a preview that won't start keeps the builder's message on its `Build` row for the operator. Publish's "changed since" refusal is the one builder message passed on as written: never put any other `BuilderError`'s message in a `ToolError`. Each guard has a database test that fails without it.
